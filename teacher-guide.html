BAKE / AI 合作課程教案小組交件工具 ↗

高職餐飲科二年級 · 120 分鐘 · 每組 2–3 人

全班合作，
完成 AI 糕點食譜大全。

每組負責一種新糕點；老師將全班照片與食譜統整成一個模型、一份食譜與一個網站。

課程成果

  • 每組交出約 30 張訓練照片、另留 3–5 張測試照，以及一筆三欄食譜。
  • 老師將各組照片加入同一個 Teachable Machine 專案，重新訓練全班模型。
  • 把統整食譜與新模型設定放到 GitHub，學生手機開啟同一網址，測試彼此的作品。
重要：模型網址不會自動合併。各組必須交原始照片；老師要把全部類別的照片放在同一個專案內重新訓練，才能得到全班共用的模型。

教師課前準備

準備已部署的 GitHub Pages 網站、可編輯的 Teachable Machine 原始專案、三種基礎糕點的照片與食譜，以及統一交件位置。若要保留蛋塔、瑪德蓮、布朗尼的辨識，原始專案必須保留這三類訓練資料。只有已匯出的模型網址，無法還原全部訓練照片；找不到原始專案時，請先補齊這三類照片。

預先分配各組不同糕點，例如司康、可麗露、泡芙、馬卡龍；避免同名重複。每組建議一台電腦蒐集整理照片、一支手機做最後測試；Teachable Machine 訓練以教師電腦示範。先確認學校網路能使用 GitHub Pages、Teachable Machine 與模型程式。

兩小時教學流程

時間教師帶領學生交付或檢核
0–10 分用三種基礎糕點示範拍照找食譜。說出模型看照片、食譜提供內容。
10–20 分分組、分配不同糕點、示範交件格式。確定組別、糕點名稱與分工。
20–45 分指導多角度、光線與授權來源。約30張訓練照，另留3–5張測試照。
45–60 分示範小組交件工具，說明材料與步驟。匯出本組食譜CSV，記錄照片來源。
60–75 分巡組檢查照片與食譜，收取各組資料。檢查名稱、照片數、三欄資料，交完整資料夾。
75–100 分新增各組類別、上傳照片、重訓全班模型；合併CSV並更新GitHub。觀察一個模型如何包含全班類別；完成較快組可協助檢查。
100–115 分引導跨組測試、紀錄誤判與食譜顯示。用保留照片測本組與另一組的糕點。
115–120 分成果分享與離堂提問。說出新增糕點必須同時更新的兩項資料。

訓練與網站發布時間依班級類別數、設備及網路而異。老師應先建立原始專案與交件資料夾，保留統整時間；課程不包含實際烘焙。

學生操作 四個步驟

  1. 找一種新糕點。由老師分配，確認類別名稱，例如「司康」。照片、食譜與模型都用相同名稱。
  2. 蒐集約30張訓練照。每張主要只有一種糕點，變換角度、背景與光線，去除重複照片，另留3–5張不參與訓練。優先自拍；使用網路圖片需記錄來源與授權，避免人臉與個資。
  3. 填一份食譜。開啟小組交件工具，輸入組別、名稱、材料與步驟，材料一行一項、步驟一行一步，寫明分量、溫度、時間。下載CSV與說明檔。
  4. 整理交件。資料夾命名「03_司康」，內含「訓練照片」「測試照片」、本組食譜CSV與來源說明。用老師指定的資料夾或交件平台提交；網站本身不會自動上傳照片。

教師統整 六個步驟

  1. 檢查交件。確認照片數量、授權與食譜三欄；糕點名稱不重複。
  2. 建立全班模型。開原始 Teachable Machine 影像專案，保留原三類；每組新增一個同名類別，分別批次上傳該組訓練照片。不要把所有照片放在同一類。按訓練，以保留照片測試，再匯出 TensorFlow.js 並上傳，取得新的模型連結。
  3. 合併全班食譜。在首頁展開「教師設定與全班統整」，勾選保留現有三款食譜，選擇各組CSV。確認合併成功，下載 recipes.csv。重複名稱或缺欄會阻擋合併。
  4. 檢查新連結。貼新模型連結，食譜來源保留 recipes.csv。按「檢查並在本機試用」，網站會用剛合併的食譜檢查類別對應，並實際載入模型。通過後可用照片試辨識。
  5. 公布全班版本。下載 config.json，把它與剛合併的 recipes.csv 一起上傳至 GitHub 儲存庫根目錄，覆蓋舊檔並 Commit changes。等待 GitHub Pages 發布完成。只有在教師電腦按試用，不會更新同學的裝置。
  6. 全班測試。所有人重新整理同一網站，確認顯示「全班公布版本」。用未訓練的照片交叉測試，記錄正確數與誤判原因。不要把單張信心值當成整體準確率。

Google 試算表也可繼續使用

三欄格式固定為「辨識名稱、材料、步驟」，每種糕點一列，格內換行。老師可將合併的CSV匯入自己的Google試算表，或把各組資料整理在同一工作表。教師設定可改貼已開放讀取的Google食譜連結，檢查通過後下載config.json並上傳GitHub。之後只改同一份Google食譜，不用重傳config.json；學生按重新讀取即可取得目前可讀到的內容，Google更新可能有延遲。建議公開的工作表只放食譜，不放學生個資。

GitHub Pages 最短部署方式

  1. 建立 GitHub 公開儲存庫，例如 pastry-classroom。
  2. 解壓縮簡化版ZIP，把套件內檔案放到儲存庫根目錄。首頁 index.html、config.json、recipes.csv 必須在根目錄，不要只上傳ZIP，也不要再多包一層資料夾。
  3. 到 Settings → Pages → Source 選 Deploy from a branch → 分支 main → 資料夾 /(root) → Save。
  4. 等待發布完成，使用 Pages 顯示的 HTTPS 網址。學生以手機或平板瀏覽器開啟，不需GitHub帳號。

不需要Cloudflare帳號、API Token、Secrets、npm安裝或額外後端。網站要更新時，由有GitHub儲存庫編輯權的老師上傳檔案。需要回復舊設定時，可從GitHub檔案History找回舊config.json與recipes.csv，重新提交。使用Google來源時，GitHub只保留連結版本，不會備份Google原表內容。

常見問題與評量

  • 網站一直辨識成舊糕點：確認已重訓包含新類別的全班模型、config.json已上傳成功、學生已重新整理。只有新增食譜不會讓模型學會新類別。
  • 低於80%：提示可能是未收錄的新糕點；光線與角度也可能造成低信心，先重拍。未知物件仍可能被模型高信心誤判。
  • 找不到食譜：確認模型類別與食譜名稱完全一致，例如「蛋塔」與「蛋撻」不會自動對應。
  • 只有老師看到新版：老師可能還在「本機試用」。須把config.json與recipes.csv上傳GitHub後，全班重新整理。
  • 手機無法開相機：用HTTPS網址及外部瀏覽器，允許相機，或改用系統相機拍照後上傳。
